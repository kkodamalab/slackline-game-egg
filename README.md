# シーソーゲーム：〇〇を落とすな！

GiBoard／スラックラインの傾き、カメラで見た身体軸、PCのキーでシーソーを操作する子供向けゲームです。2026年10月18日、南大沢・大平公園の「風に立つ」を想定しています。

公開先（このブランチの公開完了を意味しません）：https://kkodamalab.github.io/slackline-game-egg/

## 起動とチェック

Node.js 20以降。ゲーム本体はビルド不要、TILT・PC TEST・画像加工は外部パッケージなしで動作します。BODY AXISはカメラ許可とMediaPipe配布先への通信、PHONE CONTROLLERは元のPeerJSサービスとWebRTCの通信が必要です。BODY AXISのカメラ映像は送信しません。PHOTO GIFTは明示操作・了承確認後だけ、受信スマホへ完成PNGをWebRTCで転送します。画像のクラウド保管は行いません。

```sh
npm ci
npm test
npm run check
npm start
```

開発サーバーはHTTP、ポート4173（`PORT`で変更可）。静的配信は `index.html`、`styles.css`、`src/` を配置します。既存GitHub Pages設定は変更しません。

ブラウザーテストはPlaywrightを開発依存として使用します。クラウドでは導入済み `/usr/bin/chromium` を使います。他の環境では以下を実行します。

```sh
npx playwright install chromium
npm run test:browser
```

WindowsでChromeが導入済みの場合、PowerShellで `$env:BROWSER_CHANNEL="chrome"` を設定して `npm run test:browser` を実行することもできます。任意のChromium実行ファイルは `BROWSER_PATH` で指定できます。

## あそびかた

選ぶ順番は **ゲームモード → オブジェクト → 入力方式 → 難易度** です。初期選択はKEEP・たまご・PHONE CONTROLLER・かんたん。写真系を選んだ場合、画像を決定してから開始します。

| モード | 終了 | 得点・復帰 |
|---|---|---|
| KEEP | 設定時間（5〜60秒） | 落下回数。落下しても1.4秒後に復帰。0回なら特別演出 |
| STAR | 設定時間（5〜60秒） | 安全ゾーンに連続2秒で落ち葉1枚、最大floor(設定秒数 / 2)個。落下しても取得済みの落ち葉は保持 |
| SURVIVAL | 最初の落下／設定時間 | 生存時間。設定時間を達成すると完全成功 |

すべてのモードで、一時停止中は時間・物理・統計が進みません。結果の「もういっかい」は選択を維持し、PHONE CONTROLLERではスマホの中心設定を保持、その他の入力では再度中心設定、「べつのゲーム」は設定画面へ戻ります。

### PCで試す

1. 入力を「PC TEST」にする。
2. 「② まんなかにする」→「あそぶ！」。
3. ←／→は2度ずつ、Spaceは絶対入力角0度。スライダーは±30度。
4. KEEPは落とさず30秒、STARは中央で落ち葉15枚、SURVIVALは30度を維持して最初の落下で終了することを確認できます。
5. 結果でCSVまたは「おみやげフォトをつくる」→「PNGを保存」。

0度以外で中心設定した場合、その角度がゲームの水平です。Spaceは中心設定を解除しません。

### LOCAL TILT／端末自身の傾斜

1. **HTTPS**の公開ページをSafariで開く。HTTPのLAN開発サーバーではセンサーが使えない場合があります。
2. スマホが落ちないようGiBoard等に固定する。
3. LOCAL TILTを選択し、「① センサーをつかう」→許可。
4. 基準姿勢で「② まんなかにする」→「あそぶ！」。
5. 画面回転では一時停止して中心設定し直します。入力が2.5秒以上停止した場合も一時停止します。

画面0°はgamma、90°は−beta、180°は−gamma、270°はbeta。右端を物理的に下げるとシーソーの右端も下がります。EMA alpha=0.24、中心設定時のraw角をbaselineにし、研究用相対角は±180°でラップ、ゲームだけ±30°に制限します。裏返し・Euler角特異点を横切る大回転は対象外です。

### BODY AXIS／カメラ配置

1. HTTPS（またはPCのlocalhost）でBODY AXISを選択。「① カメラをつかう」→許可。
2. カメラを参加者の正面に、水平に固定。肩と腰が映る距離に置く。全身の33点すべてが見える必要はありません。
3. まっすぐ立ち「② まんなかにする」→開始。結果表示時にカメラを停止します。再プレイ時は①で再接続してください。
4. スタッフ設定で感度0.5〜2、入力の左右反転、プレビュー鏡表示、スケルトン、肩・腰・軸の表示、プレビュー非表示を調整できます。

MediaPipe Pose Landmarker（33点、tasks-vision **0.10.32**、Liteモデル）を使用。左右肩の中点と左右腰の中点から、画像の縦横比を反映したピクセル座標で `atan2(肩x−腰x, 腰y−肩y)` を計算します。必要4点のvisibility/presence最小値が0.6未満、胴体が短すぎる、肩が腰より下の場合は有効入力にしません。検出ロストは即時、映像停止は500msで一時停止します。

カメラ座標で画像右への傾きが正。対面カメラ用の入力反転は初期ON、鏡プレビューも初期ONですが、互いに独立しています。身体軸の相対角を研究用に保存し、感度はゲーム角だけに適用します。配置が逆の場合はスタッフが入力反転を変えて中心設定し直してください。

初回ロードに以下への通信が必要です：

- `cdn.jsdelivr.net`：固定バージョンのJS／WASM
- `storage.googleapis.com`：MediaPipe Lite `.task` モデル

ロード失敗時はTILTかPC TESTに切り替えられます。このブランチのクラウド検証では、モデル配布先がCONNECT 403のため実モデルによる人物検出は未検証です。カメラ接続・検出ロスト・復帰・切替は模擬33点でテストしています。

## PHONE CONTROLLER（イベント用標準）

PCはゲーム画面、スマホはGiBoardに固定する傾斜センサーです。端末自身でゲームを表示するLOCAL TILTとは別入力です。

1. PCでHTTPS公開URLを開き、PHONE CONTROLLERを選ぶ。
2. PCに表示される240pxのQRをスマホで読む。ROOMは事前に確定するHostのPeer IDで、サービス接続待ちでもQRは表示します。未接続と接続済みは状態表示で区別します。接続URLは同じ公開サブパスの `?room=...&player=A`。
3. スマホのController専用画面で「センサーをON」→許可。安全に固定し、「まんなかにする」。
4. PCの接続・センサーON・中央設定が揃ったら「あそぶ！」。PCの「スマホの中央姿勢を設定」でもスマホへ中央設定を要求できます。
5. 左右に傾けるとPCのシーソーを操作。スマホの回転、センサー停止、通信停止、タブ離脱でPCが一時停止します。
6. 切断時は自動再試行。スマホの「PCにつなぎ直す」、PCの「再接続」は同じROOMへ再接続。PCの「ROOMを作り直す」やページ再読込では、新しいQRを読み直してください。再接続後はPCの「つづける」で手動再開。

スマホの中央設定とEMAはスマホ側で実施し、PCで二重に処理しません。入力切替では古いROOM・接続を破棄します。接続完了後はQR領域が折りたたまれ、見出しを押すと再表示できます。画像・写真は送信せず、約30Hzで傾斜角と接続／中心設定状態のみPCへ送信します。メタデータにはinputMode=phone、roomId、模擬／実入力区別、中心設定履歴を記録します。

元の `feat/pc-host-controller` のPeerJS **1.5.5**／QRCode.js **1.0.0**、PeerBus・パケット形式を再利用。PeerJSの既存デフォルトPeerServer `0.peerjs.com` と、同梱ライブラリのSTUN／TURN設定を維持します。新サービスや独自の本番TURN認証情報は追加していません。ネットワーク側でWebRTCを禁止する環境では接続できない場合があります。クラウドのHTTPプロキシから `0.peerjs.com` への取得はCONNECT 403を観測しました。

localhostのQRは同じPCでの試験専用です。実機はスマホから開ける同じ版のHTTPS公開URLを「接続設定」で指定するか、最初からPCでも公開URLを開いてください。

## オブジェクト・画像

プリセットはSVGでカード・ゲーム・結果・フォトに描画します。物理係数は `src/config.js` の独立テーブルで難易度に掛け合わせます。

| オブジェクト | 加速度倍率 | 減衰倍率 | 速度上限倍率 |
|---|---:|---:|---:|
| EGG／カスタム画像 | 1 | 1 | 1 |
| SOCCER_BALL / BASKETBALL / BALL（互換用） | 1.2 | 0.85 | 1.15 |
| APPLE | 0.9 | 1.1 | 0.9 |
| CHICK | 0.65 | 1.2 | 0.7 |

合成速度の上限は1.2／秒。難易度は従来の安全ゾーン・加速度・復元力・速度設定を維持します。画像内容は物理設定に影響しません。

MY FACEは前面カメラで撮影、MY DRAWINGは背面カメラで作品を撮影、MY PHOTOを含む3種類ともJPEG／PNG／WebPファイルを選択できます。拡大・左右上下の位置調整、円形／角丸トリミング、再撮影に対応。自動顔切り抜き・背景除去は実装せず、手動トリミングを使います。

25MBまでの画像を受け付け、編集用画像は最大辺1600px、ゲーム用は256pxのPNGにCanvasで再描画。元ファイルのEXIF位置情報を引き継ぎません。読み込み失敗はゲームを止めず再選択できます。写真はメモリー上のみ保持し、ページ終了・再読込で消えます。「写真と作品をすべて消す」でも破棄できます。参加者交代時はこの操作または再読込をしてください。

## PHOTO GIFT（編集・専用QR転送）

1. 結果の「おみやげフォトをつくる」から、笑顔・記念写真とお絵かき作品を独立して選択／撮影します。ゲーム用画像は自動重複表示しません。「ゲームの画像を笑顔写真に使う」で明示的に流用できます。
2. A：左右2分割、B：笑顔大、C：作品大、D：笑顔1枚、E：作品1枚。1枚だけなら空き枠を残さず大きく表示し、D/Eの指定素材がなければ利用できる別の1枚を使います。画像なしならイラストと結果カードになります。
3. 縦1080×1620／横1620×1080、拡大・左右上下のトリミング、背景5色、シンプル／ポップ／草木フレーム、タイトル・結果・イベント情報・オブジェクト名の表示を調整できます。PNGには設定時間とモード別の結果も表示します。
4. 本人・保護者の了承を確認してチェックし、「スマホにおくる」。**写真を受け取るQR**を参加者のスマホで読み取ります。ゲーム操作用Controllerとは別画面・別Peer IDです。PCは転送中、開いたままにしてください。
5. 受信側で「写真を保存」。対応機種では「共有・写真に保存」も表示します。iPhoneでダウンロード後の扱いが難しい場合は画像を長押しして写真に保存、Androidはダウンロードから保存します。実機の保存メニューはOS／ブラウザーに依存します。
6. 転送失敗・中断時は受信側「再試行」で期限内に最初から再受信できます。PCで「スマホにおくる」を再押下すると新しいQRになります。通信できない場合も「PNGを保存」は利用できます。

PeerJS 1.5.5／実WebRTC DataChannelを使用。48KiBチャンクを1個ずつACK確認し、進捗表示します。PNG上限12MiB、応答待ち15秒、セッション有効期限10分。URLには推測困難なPeer IDと256bitの一時トークンのみを含め、写真やゲーム結果は含めません。トークンを持つ人が受信できますのでQRの共有に注意してください。写真を保管するサーバー・課金・新たな認証情報はありません。接続のため既存PeerServerとSTUN／TURNを利用します。ネットワーク状況によっては通信できません。

「転送終了・一時データを破棄」で接続と送信データを破棄。「写真・作品を消す」でゲーム画像・笑顔・作品・カメラ・転送を破棄します。「次の参加者」／結果の「べつのゲーム」でも前参加者の画像をすべて破棄。「もういっかい」は同じ参加者の再挑戦として選択を保持します。受信側にも「受信写真・接続を破棄」があります。ページを閉じるとメモリーの写真は消えます。保存済みPNGは端末の写真／ファイルアプリで削除してください。画像はCanvasへ再描画してEXIFを持ち越さず、localStorage・研究CSVに含めません。

`giftData()` と `photo-gift:preview` CustomEventはメモリー内の連携用インターフェースです。

## 研究用データと互換性

約10Hzの時系列、1/120秒固定ステップでの時間重み統計、CSV、最新1試行のlocalStorage保存を維持。`EggGame` は `SeesawGame` の互換クラスとして残します。既存の `eggPosition`、`eggVelocity`、`numberOfEggDrops`、`stars` などを削除しません。

追加：gameMode、objectType、inputMode、difficulty、survivalTime、dropCount、starCount、bodyAxisAngle、trackingConfidence。inputModeはsensor（LOCAL TILT）／test／body／phone。PHONE CONTROLLERの実・模擬入力区別はcontrollerInputTypeに記録。身体軸時の角度はスマホの傾斜ではなく、反転設定後の身体軸相対角です。検出Confidenceは時系列に記録します。感度・入力反転・合成物理設定・再中心設定履歴は試行メタデータへ記録します。

mean／SD（母標準偏差）／RMSE／最大絶対角／安全ゾーン時間と割合を維持。落下復帰待ちも試行時間に含み、安全ゾーン時間には含めません。CSVには写真や画像データを含めません。

localStorageの `keep-the-egg:last-trial` は最新1試行のmetadata／summary／samplesのみ。外部送信はありません。結果CSVは現在の試行が対象です。

## 復元元と機能退行の原因

指定された `9a0549e26e20bcb41e5265ca0745d6ea13cbe56b` と最初の `8032af3` にはQR／ROOM／通信実装はありません。実装は同じリポジトリの別ブランチ `feat/pc-host-controller`、導入commit `59d646f`、配信検証まで含む先端 `ac6d103c720666181d7bdd55dacb104faffb41da` に存在します。出典は `src/peer-bus.js`、`src/remote-input.js`、`src/controller.js`、`src/qr-connection.js` と `vendor/`。さらに元はUCMゲームのPeerJS実装です（THIRD_PARTY.md）。

PR #1の拡張版はQR追加前のmainをベースにし、上記別ブランチを統合しませんでした。古い公開ブランチには存在した機能が、新mainへ取り込まれず公開元がmainになったことが欠落の原因です。拡張版がQRコードを含むcommitを直接削除したという履歴ではありません。旧ブランチのPAGES_QR_DIAGNOSIS.mdには旧版とQR版の実公開・検証記録があります。

今回、mainの拡張機能を残し、通信モジュール・Controller・同梱ライブラリを選択的に復元しました。タイトルはメイン「シーソーゲーム」、選択に追従するサブタイトルとdocument.titleを明示し、7種類すべてを自動検証します。初期EGG表示は正常です。

### 通信ブラウザーテストの環境

開発依存の `peer` はテスト専用ローカルPeerServer、`jsqr` はQR実デコードに使用し、本番に配信しません。TURN実行ファイルがない通常のChromiumでは2画面を直接接続します。CIではcoturnを導入し、同じTCP経路で試験します。`SEESAW_TURN_BINARY` またはシステムの `/usr/bin/turnserver` も使用できます。管理ポリシーで直接UDPを禁止したこのクラウドでは、Debian署名付きパッケージから展開したcoturnを `/workspace/.seesaw-test-tools/coturn/` に置き、127.0.0.1だけで試験用TURN/TCPを起動します。管理ポリシーや本番の接続設定は変更しません。テストプロセスは自分が起動したPeerServer／TURN／開発サーバーを終了します。スマホセンサーイベントは模擬ですが、傾斜パケットは実DataChannelを通過します。

公開後の静的アセット一致確認は `node scripts/verify-pages.mjs`。HTML、CSS、同梱ライブラリ、Host／Controllerのモジュールグラフを公開URLと比較します。外部PeerServerの接続や実機センサーの検証とは別です。

## 音響・時間・ボールの追加仕様

通常設定の「プレイ時間」は5〜60秒・5秒刻み、初期30秒。開始時に確定し、プレイ中は変更できません。全モードの時間、結果、PHOTO GIFT、時系列／集計CSVの `configuredDuration` に反映します。安全な中央でSTARは連続2秒につき落ち葉1枚、上限は設定時間÷2の切り捨て。既存APIのduration未指定呼び出しだけは従来値（KEEP／STAR30、SURVIVAL60）を保持します。

スタッフ設定で効果音・声を独立制御。効果音はクラクション、ホイッスル、ベル、電子音、コミカル、なし。初期ベル・効果音ON、声AUTO、BGMなし。効果音と声は各0〜100%、試聴可能、設定は `seesaw:audio` としてlocalStorageに保存します。Web Audioは「あそぶ！」／試聴のクリックで有効化し、Controllerと写真受信側では音声モジュールを読み込みません。

危険閾値0.70、非常に危険0.90、同状態の再通知2秒。安全に戻ると再通知可能。声は4秒の間隔を確保し、AUTOは危険・中央安定・落ち葉獲得・落下・成功に応じて日本語を選択。SELECTは指定のイベントに選んだセリフだけを再生、OFF／なしも可能。落下・星・成功・残り3秒の音はアラートと区別します。休止時は再生を止め、アラート時刻はゲーム時間を使用します。日本語音声の非同期取得に対応し、日本語音声がない場合は状態表示して効果音だけで継続します。閾値・間隔は `audioConfig` で変更できます。端末の日本語音声とスピーカー実音量は実機で確認してください。

選択BALLを白黒のサッカーボールとオレンジのバスケットボールに置換。SVGをカード・ゲームで共用、移動速度を積分した回転角を表示します。旧 `BALL` はデータ・呼び出し互換用として残し、同じ物理係数・速度上限を使用します。

追加テストは `test/audio-gift.test.js`、ブラウザーの音響設定・可変時間・編集・撮影・実画像転送です。画像転送では複数チャンクのPNGをPCと受信画面で完全一致比較し、保存・中断再接続・破棄・次参加者の漏れ防止を検証します。390×844／412×915は画面サイズの検証で、iPhone／Android実機の検証ではありません。

## 秋の落ち葉・開始準備・中央レイアウト

STARの内部ID・stars／starCount・2秒連続安定ルールは維持し、ユーザー表示は「落ち葉をあつめよう 🍂」へ変更。HUDは「🍂 × 枚数」、結果とPHOTO GIFTは「落ち葉を○枚あつめたよ！」。CSV時系列・集計へleafCountを追加し、従来のstarCountも残しています。制御方法は中央安全ゾーンへの維持で、キャッチ方式は追加していません。

外部画像なしのSVG3種類（黄色イチョウ、赤橙モミジ、茶色の葉）を8枚、STARの背景で9〜14.2秒周期でゆっくり流します。サイズ・回転・横流れ・揺れを変え、背景はpointer-events:none、シーソーとHUDより背面。獲得時は光る葉が0.75秒でカウンターへ飛び、枚数が増えてカウンターが跳ねます。音は従来の明るい獲得音で、ミュート・音量を維持。休止時には葉のアニメーションも停止し、結果には獲得枚数に応じて最大30枚を積みます。OSの動きを減らす設定では背景アニメーションを省き、獲得演出を短縮します。演出は物理や得点に影響しません。

全モードで「あそぶ！」→3→2→1→スタート！。準備中はセンサーを監視するだけで、時間・位置・落下・得点・研究サンプルは更新せず、台の角度は0度に固定。3秒後、現在の入力を使って1/120秒物理を開始します。準備3秒は設定プレイ時間と生存時間に含めず、metadataのpreparedAtはクリック時、startedAtは実際の開始時です。3/2/1には短い電子音、開始には別の音を使い、効果音OFF／音量0／音声非対応でも動作します。二重起動を防止し、接続断・入力停止・検出ロスト・中央設定変更／無効・タブ非表示・長い描画停止では中断して設定に戻ります。復旧後は自動再開せず、必要な中央設定の後に「あそぶ！」で3からやり直してください。開始後の既存の安全休止・手動再開は維持しています。

トップの大きな左装飾・シーソーのプレビューを削除し、コンパクトな見出しと最大660pxの設定カードを中央に配置しました。オブジェクトに応じた小さなサブタイトルは維持。PCは4列、スマホは2列のオブジェクト選択、スマホでは縦スクロール。QR／ROOM／センサー準備・全設定・スタッフ音響・カメラ・プレイ中のシーソー・結果・PHOTO GIFTは維持しています。

追加検証：ロジックのカウントダウン時刻・中断・再起動・STAR互換、ブラウザーの3モードで準備中の固定と設定時間の完全計測・二重起動・タブ／LOCAL TILT／BODY AXIS／PHONEの準備中断・葉獲得／休止・中央配置・320/390/700/1280pxの横幅。iPhone／Android／GiBoard実機と会場の操作感・音量は今回未検証です。

## UI・画像・絵文字・接触座標の修正

トップの設定カード内の重複見出しを削除。プレイ中の選択オブジェクト名、結果、PHOTO GIFTは維持します。画像カードは「ファイルを選択」「写真を撮影」の2つ。カメラは自分向き／外向きを選択でき、撮影後はファイルと同じ256pxのトリミング・拡大・位置調整を使用します。旧MY_FACE／MY_DRAWING／MY_PHOTOは物理設定・保存データの互換用として保持します。

支点の頂点・板の回転中心・地面をsceneGeometryで共通化。地面はシーン高さの80%、支点高さはmin(58px,シーン高さ×20%)、板長は幅の70%。物理位置[-1,1]を板の接線方向へ投影し、上面の接触点から法線方向へ描画半径を加えて中心を置きます。板・画像は同じ傾斜、ボールは中心回りに移動距離÷半径で回転。落下中だけ下方へ分離。物理エンジン・速度・得点・落下境界は変更していません。

「見た目」で既存SVG／OS絵文字を選択。卵・サッカー・バスケット・りんご・ひよこに加え、なし・くり・もみじ・落ち葉・かぼちゃ・きのこを追加。Apple Color Emoji、Segoe UI Emoji、Noto Color EmojiをOSに存在する範囲で使用し、フォントや画像の再配布はしません。秋の仲間は標準で絵文字。Canvasの不透明画素を測定して文字ベースライン・余白を除き、同じ256pxに正規化してゲームとPNGに使用。未対応文字が欠落グリフと同一ならSVGへフォールバック。色・形は端末のOSフォントによって異なります。実iOS／Windowsの絵文字フォント確認は未実施です。

SURVIVALの結果とPHOTO GIFTは「5.0秒 バランスできた！」形式。「次の参加者」は共通サブボタンと説明文、確認ダイアログを使用し、承認時にゲーム／記念写真／作品／転送／前試行のlocalStorageと画面上の統計を破棄。スタッフの難易度・音響・時間・入力方式は保持します。保存済みPNG／CSVは端末上のファイルなので利用者が削除してください。

PHOTO GIFTのゲーム画像流用は本人・保護者の了承チェック後の明示操作。標準オブジェクトでは無効にし理由を表示します。画像の文字列だけを引き継ぎ、PHOTO GIFTの編集値は別管理するためゲーム画像を変更しません。別写真への変更、5レイアウト、PNG保存、実WebRTCのQR転送を維持しています。
